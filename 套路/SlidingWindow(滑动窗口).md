# SlidingWindow(滑动窗口)

## 定义

滑动窗口（Sliding Window）是同向双指针技巧的一种典型应用。它的核心思想是：维护一个窗口 `[left, right)`（或 `[left, right]`），两个指针都从左端出发、向右移动。右指针负责**扩展**窗口以探索新元素，左指针负责**收缩**窗口以维持或恢复某个约束条件。通过这种方式，在一次遍历中高效地处理所有满足条件的连续子串/子数组。

```
滑动窗口（同向双指针）：

   left ────→          right ──────────→
       ↓                   ↓
 ┌───┬───┬───┬───┬───┬───┬───┬───┬───┬───┐
 │ a │ b │ c │ d │ e │ f │ g │ h │ i │ j │
 └───┴───┴───┴───┴───┴───┴───┴───┴───┴───┘
       ╰───────────────────╯
        当前窗口 [left, right)
        包含 b, c, d, e, f（不含 right 指向的 g）

两个指针都从左端出发，向右移动，窗口不断滑动
```

### 为什么需要滑动窗口？

以"无重复字符的最长子串"为例，最直觉的暴力做法是：枚举所有子串的起点 i 和终点 j，检查 `[i, j]` 内是否有重复字符，取最长的那个。

```cpp
// 暴力：O(n²) 或 O(n³)
for (int i = 0; i < n; ++i) {
    for (int j = i; j < n; ++j) {
        if (noRepeat(s, i, j)) {
            maxLen = max(maxLen, j - i + 1);
        }
    }
}
```

这样做有大量重复计算——检查 `[i, j]` 和 `[i, j+1]` 时，`[i, j]` 的部分被重复检查了。

**滑动窗口的核心优化**：不回退 left 指针。当 right 右移发现不合法时，不是重新从 `i+1` 开始，而是从当前 left 继续右移。因为已经检查过的合法部分不需要重新验证。

```
暴力：每次 i 右移，j 从 i 重新开始 → O(n²)

  i=0: [a] [a b] [a b c] [a b c a] ...   j 从 0 开始
  i=1:     [b] [b c] [b c a] ...          j 从 1 重新开始（浪费！）

滑动窗口：left 和 right 都只往右走，不回退 → O(n)

  left=0, right: [a] → [a b] → [a b c] → 'a'重复！
  left=1, right: [b c a] → ...            left 从当前位置继续，不回退
```

left 和 right 各自最多走 n 步，总共 O(n)，比暴力快一个数量级。

滑动窗口主要分为两类：

1. **可变长度窗口**：窗口大小不固定，根据条件动态扩展或收缩。常用来寻找满足某个约束的最长/最短子串或子数组。（如：找出至多包含 k 个不同字符的最长子串）

2. **固定长度窗口**：窗口大小固定为 k，窗口每次整体右移一步。常用来寻找大小为 k 的子数组中满足条件的那个。（如：找出长度为 k 的连续子数组的最大和）

第一种情况的题目更常见。

## 滑动窗口用于解决哪些问题

+ **最长/最短满足条件的子串**：给定一个字符串，找出满足某个约束条件的最长（或最短）连续子串。例如"无重复字符的最长子串"、"最小覆盖子串"。

+ **包含/覆盖类子串问题**：判断一个字符串中是否存在某个子串是另一个字符串的排列（或变位词）。例如"字符串的排列"、"找到字符串中所有字母异位词"。

+ **满足条件的子数组计数/最值**：在一个数组中，找出满足某个条件（如和 ≥ target、至多包含 k 种不同元素等）的最长/最短子数组，或计算满足条件的子数组个数。

+ **固定窗口内的统计**：在一个数组中，计算每个大小为 k 的窗口内的最大值、平均值、中位数等。例如"滑动窗口最大值"（通常结合单调队列）。

+ **字符替换/修改类**：允许最多做 k 次修改，求能得到的最长连续相同字符子串。例如"替换后的最长重复字符"。

## 什么时候考虑使用滑动窗口

拿到一道题，按下面的流程判断：

```
题目要找什么？
│
├─ 两个（或多个）「离散位置的配对」 → 不是滑动窗口，考虑相向双指针或哈希表
│
├─ 一个「目标值/分界点」 → 不是滑动窗口，考虑二分查找
│
├─ 不要求连续的「子序列」 → 不是滑动窗口，考虑动态规划或贪心 + 二分
│
└─ 一段「连续子串/子数组/子区间」
    │
    │  问 1：窗口大小是固定的 k？
    │  ├─ 是 → ✅ 固定长度滑动窗口（滑动窗口最大值、大小为 k 的子数组最大和）
    │  └─ 否 → 继续看问 2
    │
    │  问 2：题目要找的是最长/最短/恰好满足某条件的连续区间，或计算满足条件的区间个数？
    │  ├─ 是 → 继续看问 3
    │  └─ 否（如只是查询任意区间和，不涉及优化） → 可能用前缀和即可
    │
    │  问 3：约束条件具有单调性？（见下方解释）
    │  ├─ 是 → ✅ 可变长度滑动窗口（无重复字符最长子串、最小覆盖子串、至多 k 种字符的最长子串）
    │  └─ 否 → 继续看问 4
    │
    │  问 4：单调性被破坏的原因是什么？
    │  ├─ 元素有负数，导致和不单调 → 前缀和 + 哈希表（如"和等于 k 的子数组个数"）
    │  ├─ 窗口内需要复杂查询（如中位数） → 滑动窗口 + 辅助数据结构（有序集合、对顶堆）
    │  └─ 其他原因（如异或等运算本身不单调） → 不适合滑动窗口，考虑前缀和 + 哈希表或动态规划
```

**最终验证**（针对可变长度窗口）：通过上面的流程初步判断后，还需要验证一个关键条件——**当右指针右移导致窗口不满足条件时，左指针右移能恢复条件**（即窗口具有单调性）。能恢复，才说明滑动窗口确实适用。固定长度窗口不需要此验证，因为窗口大小始终为 k，不涉及动态收缩。

### 什么是"单调性"？

一句话：**扩大窗口只会让情况往一个方向变（变好或变差），不会反复横跳。** 这样缩小窗口就一定能往反方向恢复。

具体例子：

| 题目 | 扩大窗口时 | 缩小窗口时 | 有单调性？ |
|------|-----------|-----------|-----------|
| 无重复字符最长子串 | 字符变多 → 重复可能性**只增不减** | 字符变少 → 重复可能性**只减不增** | ✅ 有 |
| 和 ≥ target 最短子数组（元素非负） | 和**只增不减** | 和**只减不增** | ✅ 有 |
| 子数组和等于 k（元素有负数） | 加了负数 → 和变小；加了正数 → 和变大 | 方向不确定 | ❌ 没有 |

**有单调性** → 大了会坏，缩就能修 → left 只需要往右走，不用回头 → O(n)。

**没有单调性** → 大了不一定坏，缩了不一定能修 → left 不知道该往哪走 → 滑动窗口不适用。

## 滑动窗口的思考方法——三步法

遇到一道疑似滑动窗口的题目时，可以按以下三步思考：

1. **确定窗口的含义**：窗口 `[left, right]` 代表什么？窗口内需要维护哪些信息？（如字符计数、元素和、不同字符种类数等）

2. **确定扩展和收缩的条件**：
   - 右指针何时扩展？（通常是无条件扩展，每轮循环 right++）
   - 左指针何时收缩？（当窗口不满足条件时收缩——求最长；当窗口满足条件时收缩——求最短）

3. **确定答案的更新时机**：在窗口状态合法时更新答案。求最长时，在 while 收缩结束后（窗口重新合法）更新答案；求最短时，在 while 循环内部、每次收缩之前更新答案。

### 第 2、3 步的直觉理解

第 2、3 步是滑动窗口最容易出错的地方。核心区别取决于**你求的是最长还是最短**：

**求最长** → 你希望窗口尽可能大，所以"**不坏不修**"——窗口合法时绝不收缩，不合法了才被迫收缩，缩到刚好合法就停，然后记录答案。

```
[a  b  c  d  e]     ← 合法，长度5，不缩，继续扩
[a  b  c  d  e  f]  ← 不合法了！被迫缩
   [b  c  d  e  f]  ← 合法了，停，📝记录长度5
```

**求最短** → 你希望窗口尽可能小，所以"**够了就砍**"——窗口一旦合法，立刻记录答案，然后尝试收缩看能不能更短，直到不合法才停。

```
[2  3  1  2]     ← sum=8 ≥ 7，合法！📝记录长度4，赶紧缩
   [3  1  2]     ← sum=6 < 7，不合法了，停，继续扩
   [3  1  2  4]  ← sum=10 ≥ 7，合法！📝记录长度4，赶紧缩
      [1  2  4]  ← sum=7 ≥ 7，还合法！📝记录长度3，继续缩
         [2  4]  ← sum=6 < 7，不合法了，停
```

对应到代码：

```cpp
// 求最长
while (窗口不合法) {    // 不坏不修
    撤销 s[left];
    left++;
}
ans = max(ans, right - left + 1);  // while 外面更新

// 求最短
while (窗口合法) {      // 够了就砍
    ans = min(ans, right - left + 1);  // while 里面更新（先记录再缩）
    撤销 nums[left];
    left++;
}
```

> **记忆口诀——"长外短内"**：求最**长** → while **外**面更新；求最**短** → while **内**部更新。

## 为什么滑动窗口是正确的

滑动窗口的正确性基于一个关键性质：**当右端点固定时，满足条件的左端点具有单调性**。

以"无重复字符的最长子串"为例：

+ 对于每个右端点 `right`，存在一个最小的左端点 `left_min`，使得 `[left_min, right]` 内无重复字符。
+ 当 `right` 增大到 `right + 1` 时，窗口中多了一个新字符，可能产生重复。为了消除重复，`left_min` 只可能**不变或右移**，不可能左移。
+ 因此 `left_min` 关于 `right` 是**单调不减**的。

这意味着 `left` 指针在整个过程中只会向右移动，不会回退。左右指针各自最多移动 n 次，总时间复杂度 O(n)。

```
right 不断右移扩展窗口，left 只在必要时右移收缩窗口：

步骤 1:  [a  b  c] d  e  a  b     right=2, left=0, 窗口合法
步骤 2:  [a  b  c  d] e  a  b     right=3, left=0, 窗口合法
步骤 3:  [a  b  c  d  e] a  b     right=4, left=0, 窗口合法
步骤 4:   a [b  c  d  e  a] b     right=5, left=1, 'a'重复 → left右移到1
步骤 5:   a  b [c  d  e  a  b]    right=6, left=2, 'b'重复 → left右移到2

left 始终单调不减，不会回退 → 总移动次数 O(n)
```

**更一般的理解**：如果对某个问题，"窗口合法"这一性质满足：**一个合法窗口的任何子窗口也合法**（或反过来，**一个不合法窗口的任何扩展窗口也不合法**），那么滑动窗口就是正确的。这保证了 left 只需单调右移，不会错过最优解。

## 模板

### 模板一：可变长度窗口（求最长）

适用于：找满足条件的**最长**子串/子数组。右指针不断扩展，当窗口不满足条件时收缩左指针，每一步更新最大长度。

```
示例：找无重复字符的最长子串，s = "abcabcbb"

 0  1  2  3  4  5  6  7    ← 下标
 a  b  c  a  b  c  b  b
 L     R                    right=2, 窗口 "abc"，长度 3 ✓
 L        R                 right=3, 加入'a' → 与s[0]重复，需收缩
    L     R                 left=1, 窗口 "bca"，长度 3 ✓
    L        R              right=4, 加入'b' → 与s[1]重复，需收缩
       L     R              left=2, 窗口 "cab"，长度 3 ✓
       L        R           right=5, 加入'c' → 与s[2]重复，需收缩
          L     R           left=3, 窗口 "abc"，长度 3 ✓
          L        R        right=6, 加入'b' → 与s[4]重复，需收缩
             L     R        left=4, 窗口 "bcb" 仍重复，继续收缩
                L  R        left=5, 窗口 "cb"，长度 2 ✓
                L     R     right=7, 加入'b' → 与s[6]重复，需收缩
                      LR    left=7, 窗口 "b"，长度 1 ✓

最长无重复子串长度 = 3
```

```cpp
// 求满足条件的最长子串/子数组长度
int slidingWindowLongest(std::string s) {
    std::unordered_map<char, int> window;  // 窗口内字符计数
    int left = 0;
    int maxLen = 0;
    for (int right = 0; right < static_cast<int>(s.size()); ++right) {
        // 1. 右指针无条件扩展，将新元素纳入窗口
        char c = s[right];
        window[c]++;
        // 进行窗口内数据的一系列更新
        // ...

        // 2. 窗口不合法时，被迫收缩左指针（"不坏不修"）
        //    注意是 while 不是 if，因为可能需要连续缩多步
        while (/* 窗口不满足条件 */) {
            char d = s[left];
            window[d]--;      // 撤销操作必须和上面的 window[c]++ 对称
            // 进行窗口内数据的一系列更新
            // ...
            left++;
        }
        // 3. 到这里窗口一定合法，且是当前 right 下的最大合法窗口
        //    所以在 while 外面更新答案（"长外"）
        maxLen = std::max(maxLen, right - left + 1);
    }
    return maxLen;
}
```

### 模板二：可变长度窗口（求最短）

适用于：找满足条件的**最短**子串/子数组。右指针不断扩展，当窗口满足条件时记录答案并尝试收缩左指针。

```
示例：找和 ≥ 7 的最短子数组，nums = [2, 3, 1, 2, 4, 3]

 0  1  2  3  4  5    ← 下标
 2  3  1  2  4  3
 L        R           right=3, sum=2+3+1+2=8 ≥ 7, 长度 4, 收缩
    L     R           right=3, sum=3+1+2=6 < 7, 扩展
    L        R        right=4, sum=3+1+2+4=10 ≥ 7, 长度 4, 收缩
       L     R        right=4, sum=1+2+4=7 ≥ 7, 长度 3, 收缩
          L  R        right=4, sum=2+4=6 < 7, 扩展
          L     R     right=5, sum=2+4+3=9 ≥ 7, 长度 3, 收缩
             L  R     right=5, sum=4+3=7 ≥ 7, 长度 2 ✓ 最短！

最短子数组长度 = 2
```

```cpp
// 求满足条件的最短子串/子数组长度
int slidingWindowShortest(std::vector<int>& nums, int target) {
    int left = 0;
    int minLen = INT_MAX;  // 初始化为最大值，方便取 min
    int sum = 0;
    for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
        // 1. 右指针无条件扩展，将新元素纳入窗口
        sum += nums[right];
        // 进行窗口内数据的一系列更新
        // ...

        // 2. 窗口合法时，赶紧收缩左指针（"够了就砍"）
        //    注意是 while 不是 if，因为缩一步后可能仍然合法，要继续缩
        while (/* 窗口满足条件 */) {
            // 3. 在 while 里面、收缩之前更新答案（"短内"）
            //    因为此刻窗口合法，缩了之后可能就不合法了，所以先记录
            minLen = std::min(minLen, right - left + 1);
            sum -= nums[left];  // 撤销操作必须和上面的 sum += 对称
            // 进行窗口内数据的一系列更新
            // ...
            left++;
        }
        // 到这里窗口不合法了，不能在这更新答案
    }
    return minLen == INT_MAX ? 0 : minLen;
}
```

### 模板三：可变长度窗口（子串匹配/覆盖）

适用于：判断字符串中是否存在满足覆盖条件的子串，如"最小覆盖子串"。用 `need` 记录需要的字符，用 `window` 记录窗口内已有的字符，用 `valid` 记录已满足条件的字符种类数。

> **注意**：此模板使用左闭右开 `[left, right)` 风格——先读取 `s[right]`，再 `right++`，此时 right 已指向窗口外的下一个位置，窗口长度为 `right - left`。模板一、二使用左闭右闭 `[left, right]` 风格（right 在 for 循环中递增，循环体内 right 就是窗口右端），窗口长度为 `right - left + 1`。两种风格都正确，但写代码时需保持一致，避免混用导致 off-by-one 错误。

s 为原始串，t 为模式串。

```
示例：最小覆盖子串，s = "ADOBECODEBANC", t = "ABC"

need = {A:1, B:1, C:1}（需要覆盖的字符及个数）
valid 表示已满足的字符种类数，valid == 3 时窗口合法

right→扩展（进窗口）:
```

```cpp
std::string slidingWindowCover(std::string s, std::string t) {
    std::unordered_map<char, int> need, window;
    for (char c : t) need[c]++;  // need 记录模式串中每个字符需要的个数

    int left = 0, right = 0;
    int valid = 0;  // 已满足条件的字符种类数（某种字符的 window 计数 ≥ need 计数时算一种）
    int start = 0, minLen = INT_MAX;
    while (right < static_cast<int>(s.size())) {
        // 1. 扩展：将 s[right] 纳入窗口，然后 right++（左闭右开风格）
        char c = s[right];
        right++;
        // 进窗口：先加计数，再判断是否刚好满足
        //   为什么这个顺序？加完之后才知道这个字符是否刚好凑够了
        if (need.count(c)) {
            window[c]++;
            if (window[c] == need[c]) {  // 刚好凑够，不是 >=，因为只在"刚好"时 valid++
                valid++;
            }
        }

        // 2. 收缩：窗口已经覆盖了 t 的所有字符（合法），尝试缩小找最短（"够了就砍"）
        while (valid == static_cast<int>(need.size())) {
            // 在 while 里面更新答案（"短内"）
            //   注意：左闭右开风格，窗口长度是 right - left（不是 right - left + 1）
            if (right - left < minLen) {
                start = left;
                minLen = right - left;
            }
            // 出窗口：先判断是否会破坏条件，再减计数
            //   为什么这个顺序？减之前才能判断"这个字符是否刚好够用"
            //   进窗口是"先加再判"，出窗口是"先判再减"——顺序恰好相反
            char d = s[left];
            left++;
            if (need.count(d)) {
                if (window[d] == need[d]) {  // 减之前刚好够 → 减之后就不够了 → valid--
                    valid--;
                }
                window[d]--;
            }
        }
    }
    return minLen == INT_MAX ? "" : s.substr(start, minLen);
}
```

> **进出窗口的更新顺序口诀**：进窗口"**先加再判**"，出窗口"**先判再减**"。这保证了 `valid` 的值始终准确。

### 模板四：固定长度窗口

适用于：窗口大小固定为 k，窗口每次整体右移一步，在每个窗口位置执行统计或比较操作。

```
示例：找大小为 3 的子数组的最大和，nums = [1, 4, 2, 10, 2, 3, 1, 0, 20]

 [1  4  2] 10  2  3  1  0  20    sum=7
  1 [4  2  10] 2  3  1  0  20    sum=16
  1  4 [2  10  2] 3  1  0  20    sum=14
  1  4  2 [10  2  3] 1  0  20    sum=15
  1  4  2  10 [2  3  1] 0  20    sum=6
  1  4  2  10  2 [3  1  0] 20    sum=4
  1  4  2  10  2  3 [1  0  20]   sum=21 ✓ 最大！
```

```cpp
// 固定大小为 k 的滑动窗口
int slidingWindowFixed(std::vector<int>& nums, int k) {
    int n = static_cast<int>(nums.size());
    if (n < k) return 0;

    // 1. 先处理第一个窗口（前 k 个元素）
    //    固定窗口必须单独初始化，否则第一个窗口的结果会被遗漏
    int sum = 0;
    for (int i = 0; i < k; ++i) {
        sum += nums[i];
    }
    int maxSum = sum;

    // 2. 窗口每次整体右移一步：加入右端新元素，移除左端旧元素
    //    因为窗口大小固定，每次恰好进一个、出一个，不需要 while 循环
    //   （可变窗口用 while 是因为可能连续缩多步，固定窗口不存在这个问题）
    for (int right = k; right < n; ++right) {
        sum += nums[right];        // 新元素进入窗口
        sum -= nums[right - k];    // 旧元素离开窗口（left = right - k）
        maxSum = std::max(maxSum, sum);
    }
    return maxSum;
}
```

## 进阶技巧

### "恰好型"问题的转化

标准滑动窗口模板直接处理的是"至多"或"至少"型约束（如"至多包含 k 种字符的最长子串"）。对于"**恰好**"型约束（如"恰好包含 k 种不同字符的最长子串"），无法直接用滑动窗口，因为窗口收缩的方向不明确——窗口里字符种类多了要缩，少了也不行，不满足"大了会坏，缩就能修"的单调性。

**转化公式**：

```
恰好(k) = 至多(k) - 至多(k - 1)
```

即：恰好包含 k 种字符的子串个数 = 至多包含 k 种字符的子串个数 − 至多包含 k−1 种字符的子串个数。

这样就把"恰好型"问题转化为两次标准的"至多型"滑动窗口，每次都可以用模板一求解。

```
示例：s = "abc"，求恰好包含 2 种不同字符的子串个数

所有子串：  "a"(1种), "b"(1种), "c"(1种), "ab"(2种), "bc"(2种), "abc"(3种)

至多 2 种的子串：  "a", "b", "c", "ab", "bc"    → 5 个
至多 1 种的子串：  "a", "b", "c"                 → 3 个

恰好 2 种 = 5 - 3 = 2 个（即 "ab" 和 "bc"）
```

### 计算满足条件的子数组个数

在"至多型"滑动窗口中，当 right 固定时，所有以 `left, left+1, ..., right` 为左端点的子数组都满足条件。因此满足条件的子数组个数为 `right - left + 1`，在每一步累加即可。

**为什么是 `right - left + 1`？** 因为窗口 `[left, right]` 合法，而合法窗口的任何子窗口也合法（单调性），所以以 right 为右端点的合法子数组有：

```
[left,     right]  ← 长度最大的那个
[left+1,   right]
[left+2,   right]
...
[right,    right]  ← 长度为 1
共 right - left + 1 个
```

```cpp
// 计算至多包含 k 种不同元素的子数组个数
long long atMost(std::vector<int>& nums, int k) {
    std::unordered_map<int, int> window;
    int left = 0;
    long long count = 0;
    for (int right = 0; right < static_cast<int>(nums.size()); ++right) {
        window[nums[right]]++;
        while (static_cast<int>(window.size()) > k) {
            window[nums[left]]--;
            if (window[nums[left]] == 0) {
                window.erase(nums[left]);
            }
            left++;
        }
        // 以 right 为右端点，左端点可以是 left, left+1, ..., right
        count += right - left + 1;
    }
    return count;
}

// 恰好包含 k 种不同元素的子数组个数
long long exactlyK(std::vector<int>& nums, int k) {
    return atMost(nums, k) - atMost(nums, k - 1);
}
```

### 逆向思维：不连续 → 连续

有些题目看起来不是滑动窗口——要选的元素不连续。但反过来想，**剩下没选的部分是连续的**，就可以用固定窗口了。

以 1423 题（可获得的最大点数）为例：从一排 n 张牌的两端取共 k 张，求最大点数。

```
取两端 k 张（不连续）          剩下中间 n-k 张（连续！）
┌─┬─┬─┬─┬─┬─┬─┬─┐          ┌─┬─┬─┬─┬─┬─┬─┬─┐
│▓│▓│ │ │ │ │ │▓│    →     │ │ │▓│▓│▓│▓│▓│ │
└─┴─┴─┴─┴─┴─┴─┴─┘          └─┴─┴─┴─┴─┴─┴─┴─┘
  取的（两端）                   剩的（中间连续窗口）

最大化两端之和 = 总和 - 最小化中间长度为 n-k 的窗口之和
```

这样就把"不连续取两端"转化成了"连续固定窗口求最小和"，直接套模板四。

**适用信号**：题目要从**两端**或**不连续位置**取元素，但补集（剩下的部分）是连续的。

## 滑动窗口的关键要点

> 以下是做题时的速查清单，详细解释见前面对应章节。

+ **窗口表示**：通常使用左闭右开区间 `[left, right)` 或左闭右闭区间 `[left, right]`。选择哪种都可以，但整个代码中要保持一致。左闭右开更常见，因为空窗口可以自然表示为 `left == right`。

+ **求最长 vs 求最短**（口诀"**长外短内**"）：
  - 求最长：while(**不合法**)缩 → while **外**面更新答案（"不坏不修"）
  - 求最短：while(**合法**)缩 → while **里**面更新答案（"够了就砍"）

+ **收缩用 while 还是 if**：可变长度窗口用 `while`（可能连续缩多步）。固定长度窗口用 `if`（每次恰好进一个出一个，不需要连续缩）。

+ **进出窗口的对称性**：进窗口做了什么，出窗口就要镜像撤销。对于模板三（子串匹配），进窗口"**先加再判**"，出窗口"**先判再减**"。

+ **时间复杂度**：尽管有嵌套的 while 循环，但 left 和 right 各自最多移动 n 次，因此总时间复杂度为 O(n)，而非 O(n²)。

+ **空间复杂度**：取决于窗口内维护的数据结构。如果用哈希表记录字符计数，空间为 O(|Σ|)，其中 |Σ| 为字符集大小；如果只维护几个变量，空间为 O(1)。

+ **窗口内的数据结构选择**：根据需要统计的信息选择合适的数据结构——哈希表（字符计数）、变量（求和、最大值）、单调队列（窗口最大/最小值）、多重集合（有序窗口）等。

## 常见错误与易错点

+ **忘记在收缩窗口时更新状态**：扩展窗口时更新了窗口状态（如字符计数、求和等），收缩窗口时也必须**对称地**撤销这些更新。忘记撤销会导致窗口状态与实际窗口内容不一致。

  **为什么会错？** 比如你用哈希表记录窗口内字符计数，进窗口时 `window[c]++`，出窗口时只写了 `left++` 忘了 `window[d]--`。此时哈希表里还记着已经不在窗口里的字符，后续所有判断都会基于错误的数据。

  **自检方法**：写完代码后，把进窗口和出窗口的代码放在一起对比，确保每一行都有镜像操作。

  ```cpp
  // ✅ 正确：扩展和收缩对称更新
  window[s[right]]++;   // 扩展时增加
  right++;
  // ...
  window[s[left]]--;    // 收缩时减少（与上面对称）
  left++;

  // ❌ 错误：收缩时忘记更新 window
  left++;  // 只移动了指针，没有更新窗口状态
  ```

+ **更新答案的时机错误**：求最长时，应在 while 收缩结束后（窗口重新合法时）更新答案；求最短时，应在 while 循环内部、每次收缩之前先更新答案。放错位置会导致记录到不合法的窗口或遗漏最优解。

  **为什么会错？** 求最长时如果在 while 里面更新，此时窗口还是不合法的，记录了一个无效答案。求最短时如果在 while 外面更新，此时窗口已经不合法了（缩过头了），记录的也不是有效答案。

  **记住口诀"长外短内"就不会搞混。**

+ **窗口边界的 off-by-one 错误**：使用左闭右开 `[left, right)` 时，窗口长度为 `right - left`；使用左闭右闭 `[left, right]` 时，窗口长度为 `right - left + 1`。混用会导致长度计算错误。

  **为什么会错？** 模板三（子串匹配）使用左闭右开，`right++` 在读取元素之后，所以长度是 `right - left`。模板一、二使用 for 循环，循环体内 right 就是窗口右端，长度是 `right - left + 1`。如果在左闭右开的代码里写了 `right - left + 1`，答案会多 1。

  **建议**：选定一种风格后全程统一，不要每题换。

+ **固定窗口的初始化遗漏**：固定长度窗口中，需要先处理第一个完整窗口（前 k 个元素），然后再开始滑动。忘记初始化会导致第一个窗口的结果被遗漏。

  **为什么会错？** 固定窗口的滑动循环从 `right = k` 开始，如果没有预先计算 `[0, k-1]` 这个窗口的结果，就少算了第一个窗口。比如最大和恰好在前 k 个元素里，你就会漏掉它。

+ **可变窗口中内层 while 误写为 if**：如果窗口可能需要连续收缩多步才能重新合法，用 `if` 只收缩一步是不够的。例如在"最小覆盖子串"中，找到一个覆盖后需要不断收缩以找到最小覆盖，必须用 `while`。

  **为什么会错？** 用 `if` 只缩一步，窗口可能仍然不合法（求最长时），或者还可以继续缩得更短（求最短时），导致答案不是最优的。

  **例外**：固定窗口每次恰好进一个出一个，所以用 `if` 就够了。

+ **哈希表中删除计数为 0 的键**：有些实现在字符计数减为 0 后不删除键，这在使用 `window.size()` 判断不同字符种类数时会导致错误。要么在计数为 0 时 erase 键，要么不依赖 `size()` 来判断。

  **为什么会错？** 比如窗口里曾经有字符 'a'，后来 'a' 被移出窗口了，`window['a'] = 0` 但键还在。此时 `window.size()` 会把 'a' 也算一种，导致种类数比实际多。

  ```cpp
  // ✅ 正确：计数减为 0 时删除键
  window[nums[left]]--;
  if (window[nums[left]] == 0) {
      window.erase(nums[left]);
  }

  // ❌ 错误：不删除，window.size() 会虚高
  window[nums[left]]--;
  // window.size() 仍然包含计数为 0 的键
  ```

## 与其他技巧的对比

### 滑动窗口 vs 前缀和

|  | 滑动窗口 | 前缀和 |
|---|---|---|
| 核心思想 | 维护一个动态窗口 | 预处理前缀和数组，区间和 = 前缀和之差 |
| 适用条件 | 约束具有单调性（窗口扩大/缩小时单调变化） | 无单调性要求，适用于任意区间和查询 |
| 时间复杂度 | O(n) | 预处理 O(n)，每次查询 O(1) |
| 典型问题 | 最长/最短满足条件的子数组 | 子数组和等于 k 的个数（结合哈希表） |

**判断方法**：如果约束条件具有单调性（如"和 ≥ target"中元素非负），优先考虑滑动窗口（O(n)）。如果元素可能为负数导致单调性不成立，或需要精确查询任意区间和，使用前缀和。

### 滑动窗口 vs 相向双指针

|  | 滑动窗口（同向双指针） | 相向双指针 |
|---|---|---|
| 指针方向 | 从左端同向右移 | 从两端向中间 |
| 典型问题 | 连续子串/子数组 | 配对搜索、两端比较、分区 |
| 关键词 | "连续"、"子串"、"子数组"、"窗口" | "两个元素"、"一对"、"两端" |
| 搜索空间 | 区间 [left, right] | 配对 (i, j)，i < j |

**判断方法**：如果题目要找的是**一段连续区间**，考虑滑动窗口；如果要找的是**两个（或多个）离散位置的元素的组合**，考虑相向双指针。

### 滑动窗口 vs 二分查找

两者都可以将 O(n²) 优化到更低复杂度，但解决的问题类型不同：

|  | 滑动窗口 | 二分查找 |
|---|---|---|
| 优化目标 | 枚举所有连续子区间 → O(n) | 在有序/二段性序列中查找 → O(log n) |
| 搜索的东西 | 一段**连续区间** | 一个**分界点/目标值** |
| 核心性质 | 左端点单调不减（单调性） | 满足/不满足条件的二段性 |
| 典型问题 | 最长无重复子串、最小覆盖子串 | 查找目标值、查找边界、旋转数组 |

**交叉场景**：某些问题可以同时用两种方法。例如"长度最小的子数组"既可以用滑动窗口 O(n)，也可以用前缀和 + 二分查找 O(n log n)。当元素都为正数时滑动窗口更优；当需要处理更复杂的约束时二分可能更灵活。

### 滑动窗口 vs 动态规划

|  | 滑动窗口 | 动态规划 |
|---|---|---|
| 适用范围 | 连续子区间 + 约束单调性 | 更一般的最优子结构问题 |
| 时间复杂度 | O(n) | 通常 O(n) ~ O(n²) |
| 空间复杂度 | O(1) ~ O(\|Σ\|) | O(n) ~ O(n²) |
| 典型问题 | 最长无重复子串、最小覆盖子串 | 最长递增子序列、编辑距离 |

**判断方法**：如果问题要求**连续子区间**且约束具有单调性，滑动窗口通常比动态规划更简洁高效。如果问题**不要求连续**，或者需要考虑跳跃选择（如"打家劫舍"），则需要动态规划。

### 滑动窗口 vs 单调队列/单调栈

滑动窗口和单调队列/单调栈经常**配合使用**，而非互相替代：

+ **滑动窗口 + 单调队列**：在固定或可变长度窗口中，需要快速获取窗口内的最大值或最小值时，用单调队列维护。例如"滑动窗口最大值"。

+ **单调栈**：解决的是"下一个更大/更小元素"问题，与滑动窗口的"连续子区间"问题本质不同。
